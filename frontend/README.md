# RecAstra

Русскоязычный интерфейс для работы с записями встреч, расшифровками, требованиями и техническими заданиями. Next.js 16 + React 19 + TypeScript. Светлый рабочий кабинет по выбранному дизайн-макету.

## Запуск

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Без `NEXT_PUBLIC_API_URL` отображается явно обозначенный демонстрационный проект. В деморежиме нет настоящего аудиофайла и отправка записей отключена.

Для подключения существующего FastAPI укажите в `.env.local`:

```dotenv
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Перезапустите приложение после изменения переменной. Для production задайте адрес **до** `npm run build`: Next.js встраивает `NEXT_PUBLIC_*` в клиентский код. Адрес должен быть доступен браузеру; для HTTPS-интерфейса нужен HTTPS API. Секреты в эту переменную передавать нельзя.

## Что работает

- Рабочий кабинет, списки проектов/встреч и представление документов.
- Отправка аудио/видео до 200 МБ в FastAPI через multipart/form-data.
- Получение расшифровки и ожидание асинхронной обработки с опросом каждые 3 секунды.
- Поиск по расшифровке, фильтрация участников, переход к источнику требования.
- Воспроизведение реального аудио, если сервер передал `audio_url`.
- Функциональные/нефункциональные требования, ручное добавление и редактирование.
- Вопросы заказчику, отметки решения и ограничения проекта.
- Предпросмотр технического задания и скачивание `.md` (Markdown).
- Адаптивная компоновка, нативные диалоги, клавиатурный фокус, состояния загрузки, ошибок и пустых данных.

**Распознавание аудио и AI-анализ в этом репозитории не реализованы.** Расшифровку предоставляет FastAPI. Готовые требования, вопросы и ограничения сервер может передавать вместе с ней. Если их нет, интерфейс оставляет эти разделы пустыми; требования можно добавить вручную. ТЗ собирается из доступных требований, без генерации недостающих фактов.

Правки требований и отметки вопросов хранятся **только в памяти текущей вкладки**; перед закрытием нужно экспортировать ТЗ. На сервер они не отправляются. После правок приложение предупреждает при закрытии/перезагрузке вкладки. Постоянное сохранение и авторизация требуют согласования API.

## Предлагаемый контракт FastAPI

В исходном репозитории не было API-контракта. Ниже — **предлагаемый**, а не подтверждённый контракт существующего сервера. Если ваши маршруты/поля отличаются, адаптируйте `lib/api.ts` и `lib/meeting.ts`.

| Метод | Маршрут | Ответ |
| --- | --- | --- |
| GET | `/meetings` | Массив объектов Meeting (включая расшифровки) |
| POST | `/meetings` | Meeting; HTTP 200/201/202 |
| GET | `/meetings/{id}` | Текущий Meeting |

POST принимает поля `file` (UploadFile) и `title` (строка) в multipart/form-data. Заголовок Content-Type выставляется браузером автоматически. Не нужно ждать окончания распознавания в POST: верните Meeting со статусом `processing`, затем отдавайте результат по GET. При ошибке обработки — `failed`. Время начала реплик и источники требований — в **секундах**.

```json
{
  "id": "meeting-1",
  "title": "Сервис онлайн-записи",
  "date": "2026-09-10T10:00:00+03:00",
  "filename": "meeting.mp3",
  "duration": 2537,
  "status": "ready",
  "audio_url": "http://localhost:8000/media/meeting-1.mp3",
  "transcript": [
    { "id": "s1", "speaker": "Заказчик", "start": 754, "text": "Клиент должен сам выбрать удобное время." }
  ],
  "requirements": [
    { "id": "r1", "title": "Онлайн-запись", "description": "Клиент выбирает свободное время.", "category": "functional", "source": 754 }
  ],
  "questions": [
    { "id": "q1", "text": "За сколько часов можно отменить запись?", "source": null, "resolved": false }
  ],
  "constraints": ["Без онлайн-оплаты на первом этапе."]
}
```

Обязательны `id`, `title`, `date`, `filename`, `duration`, `status`, `transcript`. Для `processing` допускаются `duration: 0` и `transcript: []`. `requirements`, `questions`, `constraints` необязательны и по умолчанию пустые. `audio_url` необязателен, поддерживает абсолютный HTTP(S) URL или путь от корня сервера. `category`: `functional` / `nonfunctional`. `source` — неотрицательное число или `null`. Идентификаторы должны быть уникальны внутри каждого массива. Ответы проверяются до отображения.

Настройте FastAPI `CORSMiddleware` для origin фронтенда (например, `http://localhost:3000`) и методов GET/POST. API пока не использует авторизацию или cookie credentials. Для закрытых аудиозаписей сервер может возвращать временный подписанный URL. Проверку типов и размеров загружаемых файлов необходимо также выполнять на сервере.

## Структура ТЗ (версия 3)

Правый блок содержит три открытых раздела: функциональные требования, нефункциональные требования (включая ограничения) и открытые вопросы. В карточке требования справа указана роль. Карандаш открывает редактор. Кнопка `?` переключает отметку «Требуется уточнение» и выделение карточки. Решённые вопросы переносятся в раскрываемый список, откуда их можно вернуть в открытые.

Дополнительные необязательные поля API:

- `Requirement.role`: строка, например `Пользователь`, `Разработчик`, `Владелец`. Без поля показывается «Роль не указана».
- `Requirement.needs_clarification`: boolean.
- `Question.needs_clarification`: boolean.
- `Question.constraint_index`: индекс связанного ограничения в `constraints` (целое число от нуля). Индекс должен существовать; допускается один связанный вопрос на ограничение. Кнопка уточнения ограничения создаёт связанный вопрос или переключает его решение.

Старые ответы FastAPI без этих полей остаются совместимыми. Роли и отметки включаются в Markdown и предпросмотр ТЗ. Правки по-прежнему хранятся в памяти вкладки до экспорта. Макет реализован в `components/requirements-board.tsx`.

Для обновления с версии 2 замените папки `app`, `components`, `lib` файлами из нового архива. `.env.local` менять не требуется; новые зависимости не добавлены.

## Анализ разговора — версия 4 (актуальная)

Вместо трёх групп из версии 3 теперь семь самостоятельных контейнеров:

| `kind` | Раздел |
| --- | --- |
| `functional` | Функциональные требования |
| `scenarios` | Пользовательские сценарии |
| `roles` | Роли пользователей |
| `constraints` | Ограничения |
| `conditions` | Важные условия |
| `questions` | Открытые вопросы |
| `agreements` | Договорённости |

У каждой карточки есть добавление, редактирование, удаление и отметка «Требует уточнения». Последнее удаление можно отменить. Заголовки семи разделов фиксированы; операции выполняются над карточками внутри них. Для вопросов сохранена отметка решения. Источники и роли сохраняются при редактировании. Предпросмотр и экспорт используют одни и те же семь разделов.

FastAPI может передать необязательный массив `analysis` в объекте встречи:

```json
{
  "analysis": [
    {
      "id": "item-1",
      "kind": "scenarios",
      "title": "Запись на встречу",
      "description": "Клиент выбирает специалиста и свободное время.",
      "source": 754,
      "role": "Клиент",
      "needs_clarification": false
    }
  ]
}
```

Это фрагмент ответа: обязательные поля встречи и `transcript` остаются как в основном контракте. В карточке обязательны `id` (уникальный непустой), `kind`, `title`, `description` (может быть пустой), `source` (секунды или null). Поля `role`, `needs_clarification`, `resolved` необязательны. `resolved` используется для вопросов.

**При наличии `analysis` именно он является источником данных интерфейса и ТЗ**, даже если массив пуст. Старые `requirements`, `constraints`, `questions` не добавляются повторно. Без `analysis` выполняется совместимое преобразование: функциональные требования идут в `functional`, нефункциональные — в `conditions`, ограничения — в `constraints`, вопросы — в `questions`. Новые разделы остаются пустыми до получения или ручного ввода данных. Серверные данные не дополняются примерами.

При первом редактировании создаётся полный `analysis` в памяти текущей вкладки. Все последующие операции и экспорт используют его. Серверное сохранение не добавлялось: экспортируйте ТЗ перед закрытием страницы.

Обновление с предыдущих версий: замените папки `app`, `components`, `lib` из архива. Новых зависимостей нет, `.env.local` оставьте свой.

## Версия 5

Контейнер «Роли пользователей» убран из рабочего кабинета, предпросмотра и экспорта ТЗ. Осталось шесть разделов. Поле роли внутри карточек сохраняется. Старые записи `analysis.kind: "roles"` по-прежнему принимаются от FastAPI и остаются в данных встречи для обратной совместимости, но не показываются отдельным разделом.

Обводка контейнеров чередуется: синяя / фиолетовая. При наведении мыши контейнер плавно увеличивается на 1,2%. На сенсорных экранах и при настройке уменьшения движения масштабирование отключено.

## Версия 6 (актуальная)

Вкладка «Техническое задание» удалена. Раздел назван «Анализ разговора». Экспорт ТЗ в Markdown сохранён. При наведении увеличивается отдельная карточка, а контейнер остаётся неподвижным; чередующаяся обводка контейнеров сохраняется.

Актуальные запросы, тела, ответы, параметры FastAPI и предлагаемый формат сохранения правок: [docs/API.md](docs/API.md). Готовые JSON-примеры: `docs/api-examples/`. Запрос сохранения описан как предложение и пока не подключён; три существующих запроса к серверу не изменены.

Для обновления с v5 замените `app/page.tsx`, `app/globals.css` и `components/requirements-board.tsx`. Новых зависимостей нет.
