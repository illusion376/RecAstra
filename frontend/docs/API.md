# API для RecAstra — актуальный контракт фронтенда

Это предлагаемый контракт под код `lib/api.ts`, а не описание проверенного работающего сервера. Фронтенд не распознаёт аудио. FastAPI возвращает расшифровку и готовый анализ.

## Запросы, которые уже делает фронтенд

Базовый адрес берётся из `NEXT_PUBLIC_API_URL`, например `http://localhost:8000`. JSON-ответы возвращаются напрямую, без обёрток `data`/`result`. Идентификаторы — строки, время — секунды.

| Метод | Путь | Тело запроса | Успешный ответ |
| --- | --- | --- | --- |
| GET | `/meetings` | Нет | 200, массив полных Meeting; если встреч нет, `[]` |
| POST | `/meetings` | multipart/form-data: `title`, `file` | 200/201/202, полный Meeting |
| GET | `/meetings/{id}` | Нет; ID передаётся в пути | 200, полный Meeting |
| GET | URL из `audio_url` | Нет | Аудиофайл; запрос выполняет браузерный плеер |

Не отправляйте JSON-тело в GET. В POST передавайте бинарный файл, а не путь к нему или Base64. Не выставляйте Content-Type вручную при использовании FormData: браузер сам добавит boundary.

### 1. Загрузка новой встречи

Поля тела `POST /meetings`:

| Поле | Тип | Пример |
| --- | --- | --- |
| `title` | строка | `Сервис онлайн-записи` |
| `file` | файл | бинарное содержимое `meeting.mp3` |

Пример запроса для Windows CMD:

```bat
curl.exe -X POST "http://localhost:8000/meetings" -F "title=Сервис онлайн-записи" -F "file=@C:\Records\meeting.mp3"
```

В Postman выберите Body → form-data, `title` как Text, `file` как File.

Ответ HTTP 202, пока сервер обрабатывает запись:

```json
{
  "id": "meeting-001",
  "title": "Сервис онлайн-записи",
  "date": "2026-09-10T10:00:00+03:00",
  "filename": "meeting.mp3",
  "duration": 0,
  "status": "processing",
  "transcript": [],
  "analysis": []
}
```

Фронтенд опрашивает `/meetings/meeting-001` каждые 3 секунды, пока `status` равен `processing`. POST должен вернуть JSON с Meeting, а не только `{ "id": "..." }` и не пустой HTTP 204. Возвращайте 202 быстро, продолжая распознавание в фоне. У загрузки есть таймаут 120 секунд; текущий POST не поддерживает ключ идемпотентности.

### 2. Получение результата

```http
GET /meetings/meeting-001
```

Тела запроса нет. Полный пример готового ответа находится в `api-examples/meeting-ready.json`: он содержит расшифровку и по карточке каждого из шести разделов.

Для ошибки фоновой обработки верните Meeting с `status: "failed"`; обязательные поля, `transcript: []` и `analysis: []` сохраняются. Ошибки самого HTTP-запроса возвращайте статусами 4xx/5xx, например 404. Текущий фронтенд показывает код HTTP, но не читает серверный `detail`.

### 3. Список встреч

```http
GET /meetings
```

Тела запроса нет. Ответ — массив **полных** объектов, аналогичных `meeting-ready.json`. Текущий фронтенд открывает встречу из списка и не делает отдельный GET для готовой встречи, поэтому урезанного списка `{id,title}` недостаточно. При необходимости пагинации или отдельной загрузки деталей потребуется изменить адаптер.

### 4. Аудиофайл

`audio_url` необязателен. Можно вернуть абсолютный URL `https://api.example.com/media/meeting-001.mp3` или путь от корня сервера `/media/meeting-001.mp3`. Если файла нет, **не передавайте поле** (null не поддерживается).

Аудио отдаётся с подходящим Content-Type, например `audio/mpeg`. Поддержка HTTP Range и ответа 206 нужна для удобной перемотки больших файлов. Браузерный плеер не добавляет пользовательский Authorization: для закрытого файла используйте доступный ему временный подписанный URL.

## Структура Meeting

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | string | Да | Уникальный ID встречи |
| `title` | string | Да | Название проекта/встречи |
| `date` | string | Да | Рекомендуется ISO 8601 с часовым поясом |
| `filename` | string | Да | Имя записи |
| `duration` | number | Да | Длительность в секундах, неотрицательное число |
| `status` | string | Да | `processing`, `ready`, `failed` |
| `transcript` | array | Да | Реплики; пока не готовы — `[]` |
| `audio_url` | string | Нет | Абсолютный HTTP(S) URL или путь от корня сервера |
| `analysis` | array | Нет | Карточки анализа; рекомендуемый формат |

Реплика:

```json
{ "id": "s1", "speaker": "Заказчик", "start": 754, "text": "Клиент выбирает удобное время." }
```

Все четыре поля обязательны. `start` — секунды, не строка `12:34`. ID реплик уникальны внутри встречи.

Карточка анализа:

```json
{
  "id": "a1",
  "kind": "functional",
  "title": "Онлайн-запись",
  "description": "Клиент выбирает специалиста, дату и свободное время.",
  "source": 754,
  "role": "Клиент",
  "needs_clarification": false
}
```

Обязательны `id`, `kind`, `title`, `description`, `source`. `id` и `title` непустые; ID уникальны во всём массиве `analysis`. `description` может быть пустой строкой. `source` — неотрицательное число секунд или null, если источника нет. `role` — необязательная строка. `needs_clarification` и `resolved` — необязательные boolean; `resolved` используется для вопросов.

| `kind` | Контейнер |
| --- | --- |
| `functional` | Функциональные требования |
| `scenarios` | Пользовательские сценарии |
| `constraints` | Ограничения |
| `conditions` | Важные условия |
| `questions` | Открытые вопросы |
| `agreements` | Договорённости |

Старый `kind: "roles"` принимается для совместимости, но отдельного контейнера для него нет. Не используйте его для новых ответов. Поле `role` внутри обычной карточки отображается.

Если `analysis` присутствует, даже как `[]`, он имеет приоритет над старыми `requirements`, `questions`, `constraints`. Эти старые поля можно не передавать: они по умолчанию пустые. Без `analysis` фронтенд использует совместимое преобразование старых данных, описанное в README.

## Сохранение правок: предлагаемый дополнительный запрос

**Ниже — расширение контракта. В текущем фронтенде этот запрос ещё не вызывается.** Добавление, редактирование, удаление, уточнение и отмена удаления сейчас меняют данные текущей вкладки. Экспорт `.md` формируется в браузере и не требует API.

Чтобы в дальнейшем сохранять все эти операции на сервер, достаточно одного запроса полного сохранения анализа:

```http
PUT /meetings/meeting-001/analysis
Content-Type: application/json
```

```json
{
  "analysis": [
    {
      "id": "a1",
      "kind": "functional",
      "title": "Онлайн-запись",
      "description": "Обновлённое описание требования.",
      "source": 754,
      "role": "Клиент",
      "needs_clarification": true
    }
  ]
}
```

Тело содержит **весь актуальный массив**, а не один изменённый пункт. Добавление — новый объект со стабильным UUID. Редактирование — тот же ID с новыми полями. Удаление — объект исключён из массива. Уточнение — изменён `needs_clarification`. Очистка всех карточек — `{ "analysis": [] }`. Сервер заменяет анализ целиком и возвращает HTTP 200 с полным обновлённым Meeting, не меняя расшифровку. Не применяйте этот пример с одной карточкой к заполненной встрече, если хотите сохранить остальные карточки.

При реализации совместной работы следует согласовать контроль версий; текущий интерфейс его не использует. Запросы сохранения, авторизация и серверная логика не добавлялись в этой версии.

## Настройка окружения

```dotenv
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Без значения включается деморежим. Перезапустите `npm run dev` после изменения. Для production переменная задаётся перед сборкой. FastAPI должен разрешать CORS для адреса фронтенда, например `http://localhost:3000`, методы GET/POST (и PUT при реализации сохранения), необходимые заголовки. Текущий адаптер не передаёт токены и cross-origin cookie credentials.

Фронтенд принимает MP3, WAV, M4A, OGG, WebM, FLAC, MP4 до 200 МБ; сервер должен независимо проверять формат, размер и содержимое файла.
