# RecAstra

Кейс 3 «Из разговора — в ТЗ»: веб-приложение, которое превращает запись
разговора заказчика и технического специалиста в структурированное описание
требований к продукту.

## Структура репозитория

| Папка | Что там |
|---|---|
| `frontend/` | Next.js: загрузка записи, просмотр расшифровки, правка требований, экспорт ТЗ |
| `backend/` | FastAPI: распознавание речи, анализ разговора, формирование требований |

Контракт между ними — [`frontend/docs/API.md`](frontend/docs/API.md).
Бэкенд реализует его ручками `/meetings`; параллельно у него есть более
подробный внутренний API `/api/v1/...` — см. [backend/README.md](backend/README.md).

## Запуск

Два терминала. Бэкенд (порт 8000):

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Фронтенд (порт 3000):

```bash
cd frontend
npm install
npm run dev
```

Открывать <http://localhost:3000>. Документация API — <http://localhost:8000/docs>.

В VS Code настроены конфигурации запуска: **F5 → «Всё вместе: фронт + бэк»**
поднимает оба сразу.

### Настройки окружения

Оба файла лежат в `.gitignore`, у каждого свои:

- `frontend/.env.local` — `NEXT_PUBLIC_API_URL=http://localhost:8000`.
  Без него фронт уходит в деморежим и к бэкенду не обращается.
- `backend/.env` — провайдер языковой модели и ключи, образец в
  `backend/.env.example`. Без него бэкенд поднимется в режиме извлечения
  по правилам, без нейросети.

**Ключи API в код не вписываем** — только в `.env`. Репозиторий публичный.

## Как проверить, что работает

```bash
cd backend
python smoke_test.py      # основной сценарий
python test_meetings.py   # соответствие контракту фронта
python check.py --show-source   # посмотреть результат анализа глазами
```

Тесты идут на встроенном режиме по правилам: они бесплатны, быстры
и не зависят от сети. `check.py` — наоборот, работает на настоящей модели
из `backend/.env`, каждый запуск расходует токены.
